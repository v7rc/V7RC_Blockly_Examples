# V7RC Blockly 相機物件偵測

匯入同目錄的 `camera-object-detection-percent-v2.xml`。程式啟動時顯示並清除圖層 0，開啟相機後等待 300 ms，再使用選定的物件偵測模型。每個物件會畫綠色外框，並在框的位置畫白色的「名稱 | 信心度」，例如 `cup | 87.5%`。信心度以 App 回傳的原始數值乘以 100，四捨五入並固定顯示一位小數。

使用者已在 iPhone 確認 v2 的信心度會正確顯示成一位小數的百分比。此次回報未附 App 版本、模型名稱或各診斷階段的獨立結果。

## 匯入與 iPhone 設定

1. 在網站的 V7RC Blockly 編輯器點「匯入」，選擇 XML。保留工作區的三個頂層積木：初始化、逐物件事件、整幀結果事件。
   展開初始化積木的註解，可看到「百分比版 v2 · 0.62 → 62.0%」。如在網頁匯入後要由 iPhone 讀取，先儲存到同一個裝置 ID，再於 App 編輯器按「下載」更新工作區，並確認版本註解。
2. 在 iPhone 的 V7RC App 開啟已載入此程式的 Blockly 編輯器，允許相機權限。展開初始化裡「啟用視覺 AI」的模型下拉選單，確認或選擇 App 型錄中可用的**物件偵測**模型。如果清單顯示「沒有可用模型」，先在 App 中備妥可用的物件偵測模型，再回到 Blockly 選取。一般瀏覽器缺少 App 型錄時，匯入後仍可查看及編輯積木。
3. 在 App 點「執行」。先讓兩個可辨識物件同時入鏡，再移開其中一個，最後全部移開。檢查第二幀只保留一組框與文字，收到零物件結果後圖層清空。框的位置、文字是否對齊相機預覽，以及 App 是否會送出零物件結果，需在 iPhone 確認。

交付 XML 的 `MODEL` 欄位使用型錄的 `__none__`。本機版本在載入時可由 App 提供的預設模型填入；若無預設則保留待選狀態，此時生成的程式仍會開相機，選定模型後才會產生啟動偵測的呼叫。

## iPhone 分階段測試

每個階段匯入對應 XML，在 V7RC App 執行後切回相機畫面觀察。各階段可離開並重新進入控制畫面，避免上一個測試的標註影響觀察。記錄 App 版本、iPhone／iOS 版本、模型名稱、執行前相機是否已開啟，以及各階段實際顯示。

| 階段 | 操作與預期 | 結果能確認什麼 |
| --- | --- | --- |
| 1. 畫布 | 匯入 [01-canvas-probe.xml](01-canvas-probe.xml)。無須選模型，執行後應看到相機預覽、固定綠框與黃色 `Canvas 0 OK`。 | 有預覽但沒框或文字時，記下缺少哪一項，可定位畫布顯示或原生繪圖。 |
| 2. 偵測事件 | 匯入 [02-detection-probe.xml](02-detection-probe.xml) 並選模型。先從相機關閉的狀態執行，放入模型能辨識的物件。圖層 1 應由 `Waiting for AI results` 改成 `AI results: N`。若一直等待，再開著相機重跑一次。 | 一直等待表示沒有觀察到整幀回呼。只在相機已開時成功，記為啟動時序差異。若數字大於 0，已收到偵測結果，可獨立檢查圖層 0 是否畫出物件框。 |
| 3. 連續畫面 | 沿用測試 2。依序讓兩個、一個、零個可辨識物件入鏡。記錄計數及框的位置，尤其是移到畫面邊緣時。 | 計數到 0 時舊框與文字應一起消失。若計數沒有到 0，記錄空幀回呼是否缺失。若有計數但框偏移，記錄位置和方向供查畫布座標。 |
| 4. 正式範例 | 離開並重新進入控制畫面，匯入 [camera-object-detection-percent-v2.xml](camera-object-detection-percent-v2.xml)，選模型後重跑。 | 確認只有物件框和標籤，並記錄可重現的 App 版本與模型。 |

第一輪若有落差，優先保留最早失敗的階段和截圖。若 App 的模型下拉選單一直顯示「沒有可用模型」，記下 App 版本及 App 內是否已有模型，畫布測試仍可單獨完成。
